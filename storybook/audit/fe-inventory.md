# Cards.xtra Storybook: FE inventory (components, screens, mocks)

Audited on branch `claude/storybook` (read only). Method: TypeScript compiler API over the real prop types (so prop lists are exact, not hand-read), `tsc` over `stories/**` against current props, a script that compares each story's `argTypes.options` to the current unions, and manual reads for providers. Raw helper outputs are in the scratchpad, not in the repo.

**Moving target.** `storybook/.storybook/main.ts`, `storybook/harness/*` and `stories/_spike/*` are untracked and are being edited by other agents while this audit ran. Facts about them are marked "at audit time".

Legend: **bold** prop = required. `IconName` = union of icon names (`src/atoms/Icon.tsx`, `ICON_NAMES`). `ImageSource` = `number | ImageURISource | ImageURISource[]` (Vite: PNG imports resolve to URL strings via the `require-assets-to-imports` plugin). `style` props are `StyleProp<ViewStyle|TextStyle>` and omitted.

#### Per-screen gotchas

- G1 useRefetchOnFocus (src/query/useRefetchOnFocus.ts) is used by useCards, useProfile, useEarnings, usePaymentInfo, useCardBenefits. Inside a navigator it runs `useFocusEffect` -> `refetch()` on first focus when `isFetched && !isFetching`. A cache seeded with `setQueryData` has `isFetched=true`, so the screen refetches on mount and hits the network. With no stub the refetch fails and `isError` flips true while data is kept: AdvisorScreen (`isError: cardsQ.isError`), AdvisorResults and WithdrawScreen can then show the error state. Always stub the endpoints even when seeding. useCardSavings does NOT use it.
- G2 No fixture exists for BK `/cardgenius/cards` or `/cardgenius/init-bundle`. For AdvisorScreen/AdvisorResults the data must be CardModels (via the mapper from BkCard) or a seeded `['bk','cards']` cache (the advisor engine reads CardModel fields such as `tags`, `crossSell`, `filterMeta`, `inviteOnly`; whether SAMPLE_CARDS (5 cards, src/data/cards.ts) are enough is UNSURE: not verified). For tool screens without cards the rows are league rows with no `card` (works, just no Apply or card detail).
- G3 SpendQuiz: shown answer = saved answers merged with this-run edits. The savedSpends store is a module singleton (`snapshot` in src/lib/savedSpends.ts, shared across stories), so one story's saves leak into the next. Reset with exported `clearSavedSpends()` (it also calls SecureStore delete on native). On web `canPersist` is false: memory only.
- G4 SpendQuiz / BestForBrands / BestForCategory use `useFocusEffect` + BackHandler, which require a navigation context (throws "Couldn't find a navigation object" without one). BackHandler on web is a stub.
- G5 ToolResults first render with `isLoading` shows 4 skeleton rows and text "up to a minute". To show the loading state, make the calculate stub hang. Offline state: `fetchStatus==='paused'` needs `onlineManager.setOnline(false)`. Error state: stub returns 500 (calculateSavings retries once first, up to 45 s timeout).
- G6 ToolResults tool-specific: `tool:'brands'` needs `brandIds` (TOOL_BRANDS ids) and a brands-shaped `spends` for correct column labels; `tool:'beat'` needs `highlightAlias` to match a fixture alias or "Find my card" is absent; Back uses `popTo` only after an in-screen edit (`answers !== params.answers`). Row Apply is hidden by `APPLY_ON_ROWS=false` (Apply is inside SavingsBreakdownSheet).
- G7 BeatMyCardPick/Result keep local `answers/spends` state and resync from params on change (useEffect). The pick screen needs the calculate stub (league) because the list IS the league; Result with a `cardAlias` not in the fixture shows "not found" (and fires BEAT_RESULT_VIEW verdict 'not_found').
- G8 Advisor session singleton (src/screens/advisor/advisorSession.ts `session` object): state, saved, formDraft, introDone, analytics memos persist across stories in the same page load. Seed with `getAdvisorSession().state = {answers:{opener:'first'}, held:[]}` BEFORE mount (opener ids: first, better, specific, explore; other ids: history, missing, matters, need, foodType, upi, fee, eligBridge, eligForm; answer = option id, options joined by ',' for multi, or `not_sure`); reset between stories with `resetAdvisorSession()`.
- G9 AdvisorScreen: intro mascot (`INTRO_AVATAR_SIZE` 128) shows only when `!introDone && !state.answers.opener`; messages stay skeleton until `useCards` returns >=1 card; eligibility form values (job, income, pincode) never reach analytics/route params. On web entrances are disabled (`CAN_ANIMATE_PLATFORM = Platform.OS==='ios'`). `useAnimatedKeyboard` (useKeyboardPadding) is a reanimated native-keyboard hook: may need a web shim. The dev-only "open demo" link exists only when `__DEV__`.
- G10 AdvisorResults crashes without `chips` (array) and `cardIds`; with ids not present in the cards data it shows "No cards to show".
- G11 AdvisorAvatarDemo is a `__DEV__`-only route (RootNavigator `{__DEV__ ? <Stack.Screen name="AdvisorAvatarDemo" .../> : null}`); it needs no providers except a navigation context for goBack, so it is the easiest advisor story.
- G12 Withdraw flow needs `accessToken` for data: useEarnings/usePaymentInfo are `enabled: !!accessToken`. With no token: balances stay at "—" or 0 and "Get Paid" / Verify silently return (Verify shows Alert "Session expired"). Provide an AuthProvider stub with a token string.
- G13 Payout lock: `inFlight` is a module-level boolean in src/query/mutations/withdraw.ts. A never-resolving paymentV1 stub leaves it true, so later stories throw PayoutInFlightError (busy overlay stuck). Call exported `__resetPayoutLock()` between stories. Never auto-retried; timeouts are 30 s.
- G14 WithdrawVerifyOTP: typing the 6th digit auto-submits (verify then paymentV1 then `navigation.reset` to `WithdrawSuccess`), so a story with a live stub navigates away. Reset requires WithdrawSuccess in the same navigator. Countdown starts at 30 s on mount; Resend shows at 0 ("ready") or hidden while busy.
- G15 WithdrawScreen section logic: entry `bucket` set -> one section; else both buckets >0 -> "Cashback" + "Cashback + Reward"; rewards only -> "Rewards"; otherwise "Cashback". Amount text is "—" until the first earnings load (`isLoading && !earnings`).
- G16 `usePaymentInfo` 5002/5003: serve those fixtures with HTTP 400 (not 200); the hook converts them to `paymentInProcess` / `belowThreshold` values rather than error state. Success path (doc.payment_info.json) is HTTP 200.
- G17 WithdrawSuccess/Terms/GiftCard/Amazon/Flipkart/EnterUPI render with no network except paymentInfo (EnterUPI/Amazon/Flipkart). Without a payment stub they still render (fallback ids 20/12/13).
- G18 No Android-only branches in these 16 files except KeyboardAvoidingView `behavior` (`ios` padding; undefined elsewhere) and the Android-edge-to-edge `useKeyboardPadding` (reanimated). AdvisorScreen entrances are iOS-only.

### 3.3 `src/query/queryClient.ts`

`export const queryClient = new QueryClient({ defaultOptions: { queries: { staleTime: 5 min, gcTime: 30 min, retry: (n, err) => err instanceof ApiError ? false : n < 1, refetchOnWindowFocus: true }, mutations: { retry: false } } })`.
Query keys: `src/query/keys.ts` (`qk.user.{profile,earnings,orders(filters),order(id),paymentInfo,mc.{retailers,exitDates(storeId),claims(tab)}}`, `qk.offers.{categories(parent),category(slug),store(slug)}`, `qk.cards.{list,benefits(alias)}`), plus two keys outside `qk`: `['bk','cards']` (`cardsQueryKey` in `useCards.ts`, same as `qk.cards.list`) and `['bk','calculate', spendsKey | 'idle']` in `useCardSavings.ts`.
Behaviour that matters for stories: (a) nearly every `user.*` hook is `enabled: !!accessToken`, so an unauthenticated provider means no fetch and a permanent loading or empty state; (b) seeding with `queryClient.setQueryData(key, data)` still triggers a refetch on screen focus (`useRefetchOnFocus`, `refetchOnWindowFocus`), and an unstubbed endpoint then flips the query to error, so stub the endpoint even when you seed; (c) `queryClient.clear()` between stories.

### 3.4 How the API client reaches the network

- `src/api/client.ts` re-exports from `src/api/http/*`. All CK calls go through `ck()` in `src/api/cashkaro.ts` (adds `Accept: application/vnd.api+json`, `x-chkr-app-version`, optional `Authorization: Bearer`, token refresh via `withUserToken`). All BankKaro calls go through `bk()` in `src/api/bankkaro.ts`. Both end in **`httpRequest(baseUrl, path, opts)` in `src/api/http/client.ts`**, which calls `attemptOnce` -> **`fetch(url, ...)` at `src/api/http/client.ts:136`**. This is the only `fetch(` call in `src/` and `App.js` (grep for `fetch(`, `XMLHttpRequest`, `axios`, `WebSocket`: no others). Retries: GET/HEAD retry on network/timeout/429/5xx with jittered backoff; default timeout 15 s; non-idempotent writes do not retry.
- Base URLs come from `src/config/env.ts`: `CK.baseUrl = ${EXPO_PUBLIC_API_BASE_URL}/ck`, `BK.baseUrl = ${EXPO_PUBLIC_API_BASE_URL}/bk`. **If `EXPO_PUBLIC_API_BASE_URL` is empty, `httpRequest` throws `ApiError{kind:'config'}` before reaching `fetch`**, so Vite must define `process.env.EXPO_PUBLIC_API_BASE_URL` (at audit time `main.ts` defines it as `https://storybook.invalid`, plus `EXPO_PUBLIC_STAGE="staging"` and `EXPO_OS="web"`). `CK.trackingHost` for stage `staging` is a hard-coded host used to build tracking URLs (not fetched).
- Paths to serve (under `/ck`): `/loginotp`, `/login`, `/signupotp`, `/signupV1`, `/refreshtoken`, `/users/{profile,earnings,orders,orders/:id,logout,sendotp,verify}`, `/offers/categories`, `/offers/category/<slug path>`, `/offers/<slug>`, `/payment/payment`, `/payment/paymentV1`, `/users/missingcashback/{retailers,exitclickdates/:storeId,queue,queue/:id,validate}`, `/users/tickets/<exitDate>/...`. Under `/bk`: `/cardgenius/{init-bundle,cards,cards/:alias,eligiblity (sic),calculate}`.
- **Single best stub point: replace `globalThis.fetch`** (route table keyed by URL substring, return `Response` JSON, throw `TypeError` for unmatched so the real error state shows). It is one seam, covers CK and BK, works for `useQuery`, mutations and AuthProvider's prefetches, and needs no module aliasing. The in-progress `storybook/harness/apiMock.ts` does exactly this (modes ok/loading/error/offline/empty; passes through static assets; blocks other hosts). Alternative if fetch interception proves flaky in Vite: alias `src/api/http/client.ts` to a mock exporting `httpRequest`, `basicAuthHeader`, `setHttpObserver`, `buildUrl`, `endpointLabel`, `ApiError` (heavier, and tests of error mapping would no longer run real code).
- Responses are validated against zod schemas in `src/api/schemas/*` (`contract: [name, schema]`); mismatches are reported, never thrown, so slightly wrong stubs still render but call the contract reporter (no-op in Storybook).
- Remote images (card art on `d2sriifpjiqv0p.cloudfront.net`, brand logos from CK fixtures) are real HTTPS image URLs: they leave the browser unless blocked. Decide per story: allow, or alias to local assets. `expo-image` / `RemoteImage` just set `<img src>`.
- Other network-ish modules to stub or ignore: NetInfo (`src/lib/network.ts`, only used by `OfflineBanner` and `connectOnlineManager`), Firebase (aliased to `mocks/firebase.ts`), `expo-updates` (aliased), `Linking` / `openUrl` / `useClickOut` (open tabs; see risks).

### 3.5 Session seeding (authenticated screens)

`AuthProvider` reads SecureStore on mount (aliased to the in-memory `storybook/mocks/secureStore.ts`, a module-level `Map` that is empty at start). To render as logged in, call `setItemAsync` **before** `AuthProvider` mounts: `ck_access_token` and `ck_refresh_token` (any opaque non-JWT strings: `isExpiring` returns false when no `exp` claim, so no refresh call is made), `device_unique_id` (else a UUID is generated), optionally `ck_display_name` (shown on Home/Profile) and `ck_name_pending` (`'1'` triggers the first-timer name prompt on Home). To render as guest, leave empty (`status` becomes `'unauthenticated'`). While authenticated, AuthProvider immediately calls `fetchQuery(qk.user.profile())` -> `GET /ck/users/profile`, and `signIn()` additionally prefetches earnings and profile. Stub those two routes in every authed story.
Other keys used with the same store: `cardsxtra.profile.v1` (`src/lib/savedProfile.ts`: applied cards, eligibility inputs), `cardsxtra.toolSpends.v1` (`src/lib/savedSpends.ts`: tool spend answers; `parseSavedSpends` shape in that file), recent searches (`src/lib/recentSearches.ts`, key from `storageKey(scope)` with scope `'home'` default; max 5 items `{label,...}`), onboarded flag (`markOnboarded`/`loadOnboarded`, used by Splash and Onboarding), `ck_user_id`. Because the Map is module-level it survives between stories: clear it in a decorator.

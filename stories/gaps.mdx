## How to read this file

- Severity (one rule for all audits; where the audits disagreed, this rule wins):
  - P0: the gap can lose, duplicate or misroute money (payout, withdraw), click-out attribution or cashback tracking.
  - P1: trust. A wrong number, a false empty, misleading copy or a dead end.
  - P2: polish.
- Frequency: H, M or L. It is an estimate. No usage data exists (`pm-flows.md`, "How to read this file").
- Evidence labels: no label = the cited line shows it. "Inferred" = the branch is in code, but the runtime result was not seen. "Doc only" = no `src/` evidence; listed at the end of part 1.
- IDs (N1, A2 and so on) are labels, not ranks. Rows in each group sort P0 first, then by frequency H, M, L.
- Story ids are full Storybook ids from current source. "live" in the story column = a story that shows today's wrong render.
- Paths are under `src/` unless they start with `storybook/` or `stories/`.

## 1. App gaps

### Network and offline

Root cause for N1 to N9 (inferred, not reproduced on a device): queries pause when the device is offline before the first fetch. A paused query with no data is neither `isLoading` nor `isError`, so screens fall to their empty or ₹0 branch. Only the tools handle it (`query/useCardSavings.ts:124`). There is no persisted cache (no persister in `src/` or `App.js`; `query/queryClient.ts:13`), so every offline cold start hits it. Engineering prerequisite: one shared "paused with no data = offline" helper. Pattern story: `patterns-offline--standard-offline-proposed`.

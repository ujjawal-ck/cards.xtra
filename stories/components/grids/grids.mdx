One grid component with five variants. Each variant lays out tiles of one kind in rows. The variant sets the tile, the column count and the item type.
</PageHeader>

## Variants

| Variant | Item type | Layout | Used for |
|---|---|---|---|
| `features` | `FeatureItem` (icon, label) | 2 columns by default, loading skeleton | Card benefits on card detail |
| `filters` | `FilterTileItem` (image, label, selected) | 2 per row, controlled by `onToggle` | Category filter squares |
| `brand-1x3` | `BrandOfferItem` (logo, badgeText, ctaLabel, timer) | One row of 3 | Brand offers strip |
| `brand-1x2` | `OfferCardItem` (image, ctaLabel) | Rows of 2 | Offers screen brand tiles |
| `cashback-timelines` | `TimelineStatItem` (label, metric, unit) | Rows of 2 | Store cashback timing stats |

## Composition

- `Grid` is a discriminated union: the type of `items` follows `variant`. A wrong item shape fails to compile.
- The outer width is not fixed. Put the grid in any container. Tiles share the row width equally. A trailing single tile keeps the column width.
- `filters` does not keep its own selection. The parent holds it and passes `selected` back from `onToggle`.
- `StoreCashbackTimelines` builds on the `cashback-timelines` variant. `CardDetailSheet` uses `features`. `OffersScreen` uses `brand-1x2`.
- Only `features` has a loading mode. Items from remote data need an image source the story cannot reach, so the stories here use local assets.

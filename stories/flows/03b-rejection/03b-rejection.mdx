## Flow

```
ENTRY: Ineligible sheet (after a check on a card says no; shown on every Apply)
  v
Rejection sheet
  |-- "Edit" ----------------------------> Eligibility checker (reopens)
  |-- a pick (closest | most Rewards | lifetime free) -> Home card detail -> Apply: Home gate, then click-out [MONEY]
  |-- "See all N cards you can get" -----> Cards you can get (rejection)
  |-- "Continue to Apply" ---------------> click-out [MONEY]
  v
Cards you can get (rejection)
  strip "You wanted X" -> closest row -> category chips, lifetime free, sort -> card list
  |-- tile -> Card detail sheet -> Apply: skips Home gate (R11) -> click-out [MONEY, AUTH gate]
EXIT: bank page; back to Home.
```

States: 12 live, 2 proposed, 0 hidden, 0 demo. Each state is a story; a row links to it. Screen stories use the real app screen with no network (fixtures answer every call); a proposed state is composed from design-system parts and is not in the app.

## Risks

- **R11**: A pick tapped on the sheet opens the Home card detail, so its Apply runs the Home gate. Apply on the Cards you can get page skips it. Same card, different friction. Seen in: both steps.
- **R15**: Zero alternatives (low income): the sheet drops the alternatives block and leaves only Edit and Continue to Apply. Seen in: Rejection sheet, zero picks.
- **R3**: A blocked click-out from a pick or the page is silent. Seen in: both steps (see flow 3a, Click-out).

## Open questions

- 2. Should Apply from Cards you can get run the same gate as Home? Owner: product owner.
- 3. Closing the checker (Edit) without a result: what should happen to the pending Apply? Owner: product owner.
- Zero alternatives: where does "Browse all cards" go, and should "Continue to Apply" stay for a card the bank will probably refuse? Owner: product owner.

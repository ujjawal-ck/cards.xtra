<PageHeader title="3a Card detail and apply" meta="Flow 3a · 8 steps · 31 states">
Check a card and go to the bank page with my cashback tracked. Entry: a Home tile, tile "Apply Now", a search result, a carousel, or a store page. The tools, advisor, store page and Cards you can get open this same card detail. Auth: guest, with a login gate at click-out (skippable). Money-sensitive: the click-out sets the affiliate attribution, and the eligibility verdict affects approval rate.
</PageHeader>

## Flow

```
ENTRY: Home tile / "Apply Now" / search / carousels / store page
  v
Card detail (iOS sheet | Android screen)
  |-- "View all benefits" --> All card benefits
  |-- "Learn how it works?" -> How it works sheet
  |-- share glyph -----------> Share sheet
  |-- inline checker --------> inline result banner (eligible / maybe / ineligible)
  |-- sticky Apply
  v
Apply gate (Home only, variant "mandatory")
  |-- no saved details --> Eligibility checker --> closed: Apply dropped (R2)
  |-- result sheet: Eligible ("Apply Now") | Maybe ("Continue to Apply") | Ineligible --> flow 3b
  v
Click-out  [MONEY, AUTH gate]
  |-- guest ------> Earn login sheet ("Log in to earn" | "Apply without cashback")
  |-- signed in --> user id resolved --> bank page opens outside the app
  |-- [not built] redirect step "Taking you to {bank}" (R8)
  |-- [not built] return state "Back from {bank}?" (R1)
EXIT: bank page. Back to Home, where the cross-sell rail may open (flow 3c).
```

States: 26 live, 5 proposed, 0 hidden, 0 demo. Each state is a story; a row links to it. Screen stories use the real app screen with no network (fixtures answer every call); a proposed state is composed from design-system parts and is not in the app.

## Risks

- **R1**: Return from a bank page: the app shows the same screen, with no "what happens next" and no record. Seen in: Click-out, return (proposed).
- **R2**: Closing the eligibility checker during Apply drops the Apply, with no bank page and no message. Seen in: Apply gate.
- **R3**: A blocked click-out is silent: an empty URL makes the CTA do nothing, and a missing user id shows a native alert with no event. Seen in: Click-out (proposed states).
- **R8**: No "Redirecting" step and no terms before the bank page; the tracking timeline sits behind the optional "Learn how it works?" link. Seen in: Click-out, How it works.
- **R11**: Apply from tools, advisor, Cards you can get and store best cards skips the eligibility gate Home runs. Seen in: Apply gate, Result sheets.

## Open questions

- 1. Home Apply gate: keep "mandatory" eligibility before the first Apply, or ship "skippable"? Owner: product owner (A/B setup: analytics owner).
- 2. Should Apply from tools, advisor, Cards you can get and store best cards run the same gate as Home? Owner: product owner.
- 3. When the user closes the checker opened by Apply, drop the Apply (today) or continue to the bank without a verdict? Owner: product owner.
- 5. What does the user see before and after a click-out (redirect step, terms, a "did you apply" return state), given bank approvals are not visible? Owner: product owner with the CashKaro tracking team.
- Card detail fetch failure: show "Couldn't load all benefits" with Try again, or keep failing silently? Owner: product owner.

Not storied: the card detail "first-time check opens a result sheet" path beyond the Result sheets step; the Android pager nudge (needs Platform.OS android). The click-out user-id error is a native Alert today and cannot render on web, so it is only shown as a proposal.

## Flow

```
ENTRY                               STEPS                                            EXIT
Earnings "My Order Details" ──┐
Profile "Missing Cashback" ───┤
Get Help topic (guest: login) ┤
Orders "Don't see your order" ┘
                                    Orders list ──> Order detail ──"Need Help"──┐ (no order context, R14)
                                         │                                      │
                                         └──"Don't see your order here?"───────┐│
                                                                               ▼▼
                         Claims list <───────────── Did you shop? (Yes / No)
                         (In Review | Closed | Others)        │            │
                               ▲                              │ Yes        │ No
                               │                       Where did you shop  What went wrong sheet
                               │                       (list | Oops: no     └─> Thanks sheet
                               │                        visits in 30 days)
                               │                              │
                               │                       Choose date ──> Order ID ──> Amount
                               │                                                       │
                               │            Outcome by store group (decided by the submit answer)
                               │              tracked / queued / auto-tracking  ──> Result
                               │              B1 ──> New-user check ──> Result
                               │              C1 ──> Category ──> Result (or Invoice upload)
                               │              C1 "Other" and C2 ──> Invoice upload ──> Ticket raised
                               └───── back from any outcome (useExitToClaims) ───────────┘
```

## Risks

- R13: a not-tracked claim tells the user to raise a ticket from Get Help, and Get Help restarts the same intake. See Claims list, "Not tracked with reason".
- R14: order detail "Need Help" restarts the claim from store choice; store, date and order ID are not carried. See Order detail.
- R18: invoice above about 4.4 MB fails at the BFF but the app allows 6 MB and the text says 2 MB. See Outcomes, "Invoice file too large".
- R6: offline with no cache, Orders list, Order detail, Claims list and the "Yes" answer show false empties. Stories are in Flow 10, Paused screens.
- R17: a session that ends during claim submit or invoice upload has no defined return. Stories are in Flow 10, Mid-flow return.

## Open questions

1. Carry the order's store, date and ID into the claim when it starts from Order detail? (R14)
2. Should a not-tracked claim link to a ticket for that order, instead of pointing to Get Help? (R13)
3. Which invoice size limit is real: 2 MB in the text, 6 MB in the app, or about 4.4 MB at the BFF, and should the app compress? (R18)
4. Keep a failed second page of orders as a footer message, or a full-screen error? (Orders list proposal)
5. The four hidden ticket-list screens: delete them or wire them to the API? (Claims list, hidden stories)

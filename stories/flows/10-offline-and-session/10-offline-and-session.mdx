## Flow

```
OFFLINE
  device loses network ──> Offline banner (top strip, every screen)
        │
        └─ first load with no cache ──> query PAUSED (not loading, not error)
              Home | Earnings | Offers | Orders | Order detail | Claims | Profile
                 └─> falls to its loaded or empty layout: "0 cards", ₹0, "No orders yet"  (R6)
              Proposed: one shared offline state "You're offline / Try again"

SESSION
  refresh token rejected ──> cache cleared ──> status "unauthenticated"
        └─> login sheet opens itself (source session_expired, one fixed title)
              ├─ screen behind shows a false empty ("No orders yet")
              └─ after login the user stays where they were (no onSuccess)
  during a money step (withdraw OTP, claim submit, invoice upload):
        └─> return to the step is not defined  [not built, R17]
```

## Risks

- R6: offline cold start shows false empties and a wrong ₹0. Stories: Paused screens.
- R17: session ends during a money step; the return is not defined. Stories: Mid-flow return.
- R20: the OTP rate limit shows the raw API message with no time to retry (login, not shown here; see Flow 1).

## Open questions

1. With a cache, show the last known data with a "last updated" label, or keep today's silent stale data? (R6)
2. Should the login sheet say the session ended (needs a title and body per source, DS gap 4)? (Session expired)
3. After login, return to the same step with entered values, restart it, or repeat the action on its own? (R17)
4. How long should a withdraw OTP stay valid across a login? (R17)

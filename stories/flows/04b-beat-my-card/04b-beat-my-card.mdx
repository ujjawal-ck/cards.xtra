## Flow

```
Home tools row
   |
   +-- saved spends on device -----------------+
   |                                           v
   +-- no saved spends -> SpendQuiz {next:'beat'} -> Pick list (BeatMyCardPick)
                                                          |
                                                          v
                                                 Result (BeatMyCardResult)
                                                  verdicts: best_wins, mine_wins, equal, not_found
                                                          |
                                           Full ranking (ToolResults, highlightAlias)
                                                          |
                                           Breakdown sheet -> click-out (not for the user's own card)
```

Stories reset the shared store, cache and fetch mock when they mount, so each step is its own page. Open them from the tables below.

## Risks

- R7 (score 6): the top rows of the league can be cards the app cannot sell, with no Apply and no card page. Decision D27 is directional.
- R11 (score 4): Apply from the tools skips the eligibility gate that Home runs. The user sees no verdict. A tool click-out has no gate.
- R8 (score 6): no "redirecting" step and no pre-apply terms before the click-out from the breakdown sheet.
- R6 (score 6): offline cold start. The tool results handle the paused call with "You're offline"; most other screens show a false empty state.

## Open questions

- League table scope (D27, directional): keep showing cards the app cannot sell, loss-making and discontinued cards, with Apply only in the breakdown sheet? Owner: product owner.
- Should Apply from the tools run the same eligibility gate as Home? Owner: product owner.
- What does the user see before and after a click-out (redirect step, terms, a "did you apply" return state)? Owner: product owner with the CashKaro tracking team.
